# Hermes Agent — project operating brief

Use this file as the always-on project context. The full contributor and
architecture reference remains in `AGENTS.md`; read only the relevant section
when a task requires it instead of carrying the entire document in every model
request.

## Non-negotiable invariants

- Inspect the current implementation before editing. Trace definitions, callers,
  tests, configuration flow, and original intent rather than guessing.
- Preserve a byte-stable system prompt and strict message-role alternation for
  the lifetime of a conversation. Context compression is the only normal reason
  to rewrite earlier conversation state.
- Keep the core narrow. Prefer existing extension points, then CLI + skill,
  service-gated tool, plugin, or MCP before adding a permanent core tool.
- Behavioral configuration belongs in `config.yaml`; `.env` is for credentials
  and other secrets only.
- Do not read, print, persist, or commit credentials. Do not add telemetry or
  forward API keys without explicit user opt-in.
- Do not commit, push, merge, force-update branches, or rewrite history unless
  the user explicitly asks.
- Fix the root cause and sibling paths, but avoid unrelated refactors and
  formatting churn.
- Run focused tests first, then the relevant broader checks. Never claim success
  from unexecuted tests or fabricated output.

## Efficient coding loop

1. Locate the relevant files and tests with `search_files` or terminal search.
2. Read the exact implementation and nearby conventions.
3. Make the smallest coherent change with `patch` or `write_file`.
4. Run the most focused test, lint, or build command that exercises the change.
5. Inspect the final diff and report remaining uncertainty honestly.

Batch independent reads and searches. Re-read a file after a failed patch rather
than retrying stale text. Use `todo` for multi-step work and reference code as
`path:line` instead of pasting entire files.

## Load-bearing architecture

- `run_agent.py` and `agent/conversation_loop.py`: agent construction and turn
  execution.
- `agent/system_prompt.py` and `agent/prompt_builder.py`: stable/context/volatile
  prompt assembly, skills index, and project-context loading.
- `agent/coding_context.py`: coding posture and workspace snapshot.
- `agent/context_breakdown.py`: `/context` attribution for prompt, tools, skills,
  memory, and conversation.
- `model_tools.py`, `toolsets.py`, and `tools/registry.py`: model-visible tool
  discovery and schema composition.
- `hermes_cli/`: setup, configuration, plugin discovery, and CLI commands.
- `plugins/`: optional edge capabilities. Fork-specific integrations include
  Neo4j knowledge-graph memory, RTK rewriting, cache foundation, the small-model
  context optimizer, and the local inference fleet router.
- `tests/`: behavior contracts. Prefer real imports and temporary
  `HERMES_HOME` integration tests over mocks for configuration, I/O, security,
  and provider-resolution changes.

## Small-model priorities

- Minimize always-on prose and tool-schema descriptions before shortening live
  user conversation or durable memory.
- Keep every available skill name discoverable, but load full skill instructions
  only when relevant.
- Use `agent.coding_context: focus` for coding sessions when schema size matters;
  this keeps the coding toolset plus explicitly enabled MCP servers.
- Use `/context all` and `hermes prompt-size` to measure prompt categories rather
  than optimizing by intuition.
- Preserve exact model, quantization, tokenizer, chat-template, engine-build, and
  KV-layout identity before claiming cache compatibility.
- Route heterogeneous local inference through the explicit `fleet.nodes`
  registry; never invent hosts, forward unrelated credentials, or assume two
  engines can share KV state merely because they expose the same model name.

## Fork recovery policy

The pre-reconciliation tree is preserved at
`backup/pre-upstream-reconcile-2026-07-29`. Recover useful behavior as focused
ports against current public APIs; never restore the old tree wholesale.

The configurable local inference fleet is recovered under
`plugins/fleet-router/`. The historical `agent/fleet.py` remains design evidence
only: its personal host defaults, sequential discovery, simplistic latency
routing, and key-forwarding surface must not return. Remaining recovery
candidates such as OpenCode, Paperclip, and LM Studio setup convenience require
independent current-API reviews.
